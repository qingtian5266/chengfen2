## Context

后端已有完整的微信用户模块：
- WechatUser 实体（17 个字段）
- WechatService（login, list, detail 方法）
- WechatController（/wechat/login, /wechat/list, /wechat/detail, /wechat/detail-by-openid）

当前 admin 端缺少微信用户管理界面，运营人员无法查看和管理微信用户数据。

**技术栈:**
- 后端：NestJS 10 + TypeORM（已有）
- 前端：Vue3 + NaiveUI
- 全局规范：所有 API 使用 POST 方法

## Goals / Non-Goals

**Goals:**
- 实现微信用户列表展示（带搜索功能）
- 实现微信用户删除功能
- 实现微信用户详情查看（弹窗或抽屉）
- 遵循项目 API 规范

**Non-Goals:**
- 不包含微信用户编辑（微信用户数据主要来自微信授权）
- 不包含批量操作
- 不包含微信消息推送

## Decisions

### 1. 后端接口设计
**决策:** 
- 复用现有的 `/wechat/list` 接口（返回全部数据，无分页）
- 新增 `/wechat/delete` 接口（POST 方法）
- 不需要详情接口，所有字段在列表展示

**理由:**
- 列表无分页，一次性展示所有数据
- 不需要详情弹窗，减少交互复杂度
- 遵循项目 POST 方法规范

### 2. 前端列表设计
**决策:** 
- 表格展示所有 17 个字段
- 头像列显示缩略图
- 无分页，一次性展示所有数据
- 无搜索功能
- 操作列：删除按钮

**理由:**
- 微信用户数量有限，可一次性展示
- 所有字段在列表展示，无需详情弹窗
- 头像使用缩略图展示，点击可放大（可选）
- 简化交互，减少操作步骤

### 3. 删除逻辑
**决策:** 软删除（更新 status=0）而非物理删除

**理由:**
- 保留用户数据完整性
- 便于后续数据分析和追溯
- 可恢复误操作

### 4. 路由设计
**决策:** 单一路由 `/wechat-users`（列表页）

**理由:**
- 只需要列表和删除功能
- 所有字段在列表展示，不需要独立详情页
- 简化路由配置

## Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| 微信用户数据量大，列表性能问题 | 后端 list 接口已支持分页 |
| 删除后用户无法恢复 | 使用软删除，后续可添加恢复功能 |
| openid 等敏感信息暴露 | 仅管理员可访问，已有 JWT 保护 |
| 头像 URL 可能失效 | 显示时添加默认头像兜底 |

## Migration Plan

1. **后端开发**:
   - 新增 `/wechat/delete` 接口
   - 确认 list 接口返回格式
2. **前端开发**:
   - 创建路由配置
   - 创建列表页面
   - 创建 API 调用函数
   - 实现搜索功能
3. **测试验证**: 列表、搜索、删除功能测试
